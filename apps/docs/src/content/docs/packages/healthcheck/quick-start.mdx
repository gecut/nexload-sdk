Install the core first. The `runtime: "auto"` option uses the generic runtime adapter and is appropriate when you do not need Node-specific or Bun-specific probes.

<InstallTabs packages="@nexload-sdk/healthcheck" />

<Steps>

1. Create one manager per process or service boundary.

   ```ts title="src/lib/health.ts"
   import {
     createHealthManager,
     memoryCheck,
     shutdownCheck,
   } from "@nexload-sdk/healthcheck";

   export const health = createHealthManager({
     service: { name: "api" },
     runtime: "auto",
     checks: [shutdownCheck(), memoryCheck()],
   });
   ```

2. Run the scope that matches the consumer.

   ```ts
   const report = await health.run("readiness");
   console.log(report.status);
   ```

</Steps>

## Add an external dependency

Use `httpCheck` for an HTTP dependency. Dependencies belong in readiness by default because their failure should normally stop traffic, not restart the process.

```ts
import { httpCheck } from "@nexload-sdk/healthcheck";

health.register(httpCheck("billing", "https://billing.internal/health"));
```

<Aside type="caution" title="Do not make liveness a dependency probe">
Adding database, cache, or remote HTTP failures to liveness can cause restart loops during an upstream outage. Keep liveness focused on process lifecycle unless that restart behavior is explicitly desired.
</Aside>
