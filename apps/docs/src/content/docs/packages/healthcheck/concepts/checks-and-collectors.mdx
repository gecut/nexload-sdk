Checks contribute a status to the report. Collectors add metrics and resources without independently changing the health status.

<Tabs>
  <TabItem label="Check">
    ```ts
    import { shutdownCheck } from "@nexload-sdk/healthcheck";

    health.register(shutdownCheck());
    ```
  </TabItem>
  <TabItem label="Collector">
    ```ts
    import { processMetricsCollector } from "@nexload-sdk/healthcheck-node";

    health.registerCollector(processMetricsCollector());
    ```
  </TabItem>
</Tabs>

## Choose deliberately

- Use a check when its status should affect a liveness, readiness, startup, or diagnostics report.
- Use a collector when telemetry is useful but should not change traffic or lifecycle decisions.
- Return raw metric values: number, boolean, string, or `null`.
- Keep `check.metrics` as JSON/report diagnostics. Prometheus and OpenTelemetry custom series come only from collector-produced `report.metrics`.

<Aside type="tip" title="Custom checks">
Use `defineHealthCheck` and honour the supplied `AbortSignal`. Thrown errors and timeouts are normalized into stable result entries; do not intentionally throw formatted user-facing errors from a check.
</Aside>
