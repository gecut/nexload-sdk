Every run produces a `HealthReport` with service identity, scope, status, observation time, duration, runtime identity, check results, summary, metrics, and optional resources.

## Aggregation

| Check outcome | Critical | Aggregate outcome |
| --- | --- | --- |
| `unhealthy` | yes | `unhealthy` |
| `degraded` | yes | `degraded` |
| `unhealthy` | no | `degraded` by default |
| `ok` | any | no degradation |

The default HTTP policy maps `ok` and `degraded` to `200`, and `unhealthy` to `503`. Use `STRICT_READINESS_HTTP_STATUS_POLICY` or a custom `HealthHttpStatusPolicy` when your load balancer must treat degraded readiness as unavailable.

## JSON profiles

Use `toHealthJson` or `stringifyHealthJson` to serialize a report. Public routes should omit details; diagnostics can include details only after route protection has been applied.

<Aside type="caution" title="Redaction is not access control">
Redaction reduces accidental disclosure in report data. It does not make a diagnostics endpoint public-safe. Keep the route protected as well.
</Aside>
