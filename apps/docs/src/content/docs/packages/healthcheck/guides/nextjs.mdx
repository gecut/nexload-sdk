Use the Next integration to turn a manager into `GET` and `HEAD` handlers. Routes with process or container checks must use the Node runtime and remain uncached.

<InstallTabs packages={["@nexload-sdk/healthcheck", "@nexload-sdk/healthcheck-next", "@nexload-sdk/healthcheck-node"]} />

<FileTree>

- src
  - app
    - api
      - health
        - ready
          - route.ts
  - lib
    - health.ts

</FileTree>

<Steps>

1. Export an initialized manager from a server-only module.

2. Create a readiness route.

   ```ts title="src/app/api/health/ready/route.ts"
   import { createNextHealthRoute } from "@nexload-sdk/healthcheck-next";
   import { health } from "@/lib/health";

   export const runtime = "nodejs";
   export const dynamic = "force-dynamic";
   export const revalidate = 0;
   export const fetchCache = "force-no-store";

   export const { GET, HEAD } = createNextHealthRoute(health, {
     scope: "readiness",
     format: "json",
   });
   ```

3. Use `createNextMetricsRoute` for Prometheus, OpenMetrics, or JSON monitoring output.

</Steps>

<Aside type="caution" title="Protect metrics and diagnostics">
Use the `protect` option for bearer tokens, Basic auth, IP allowlists, or CIDRs. Set `trustProxy` only when your deployment correctly supplies the configured proxy header.
</Aside>
