The exporter packages transform an already-created `HealthReport`. They do not run checks and do not require an OpenTelemetry SDK.

<InstallTabs packages={["@nexload-sdk/healthcheck-prometheus", "@nexload-sdk/healthcheck-otel"]} />

<Tabs>
  <TabItem label="Prometheus">
    ```ts
    import { toPrometheusText } from "@nexload-sdk/healthcheck-prometheus";

    const text = toPrometheusText(report, {
      prefix: "nexload",
      defaultLabels: { service: "api" },
      includeDescriptions: true,
    });
    ```
  </TabItem>
  <TabItem label="OpenTelemetry">
    ```ts
    import {
      toOtelMetricRecords,
      toOtelResourceAttributes,
    } from "@nexload-sdk/healthcheck-otel";

    const metrics = toOtelMetricRecords(report);
    const resource = toOtelResourceAttributes(report);
    ```
  </TabItem>
</Tabs>

Custom exporter metrics come from collectors in `report.metrics`; raw `check.metrics` stays in JSON/report diagnostics. Prometheus drops labels outside its controlled allowlist and emits `# HELP` for built-ins and described collector metrics when `includeDescriptions` is enabled. OpenMetrics adds the `# EOF` terminator.

<Aside type="caution" title="Label cardinality is a reliability concern">
Prometheus output accepts only a controlled label set. OTel record conversion copies labels verbatim and does not sanitize or bound cardinality. Never use user IDs, request IDs, raw URLs, raw error messages, tokens, or stack traces as labels.
</Aside>
