`moneyField` creates a Payload `number` field whose server-side value is always a safe integer minor-unit amount.

```ts
import { moneyField } from "@nexload-sdk/payload-fields";

moneyField({
  name: "price",
  currency: "IRT",
  minMinorUnits: 0,
});
```

<Tabs>
  <TabItem label="Explicit parsing">
    ```ts
    import { parseMoneyToMinorUnits } from "@nexload-sdk/payload-fields";

    const value = parseMoneyToMinorUnits("۱۲٬۵۰۰", "IRT");
    ```
  </TabItem>
  <TabItem label="Presentation">

    ```ts
    import { formatMoney } from "@nexload-sdk/payload-fields";

    const label = formatMoney(12500, "IRT");
    ```
  </TabItem>

## Contract

- REST, GraphQL, Local API, hooks, validation, and persistence use integer minor units.
- The Admin field is the only UI boundary that accepts a major-unit string.
- Floating point, unsafe integers, unsupported precision, and negative values are rejected unless `allowNegative` is enabled.
- `IRR` and `IRT` both have zero fraction digits.

<Aside type="caution" title="Do not add implicit conversion">
Calling `parseMoneyToMinorUnits` is an explicit decision at an input boundary. Do not convert arbitrary server API values from major units automatically.
</Aside>
