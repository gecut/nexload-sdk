title: Payload integration
description: Attach compiled fields and understand validation, defaults, hooks, and nested traversal.
---

The entity is not a collection builder. Keep collection lifecycle and layout native:

```ts
export const Products = {
  slug: "products",
  hooks: { beforeChange: [applyBusinessRules] },
  fields: [
    { type: "tabs", tabs: [
      { label: "Content", fields: productEntity.payload.pick(["title", "slug"]) },
      { label: "Stock", fields: productEntity.payload.pick(["inventory"]) },
    ] },
  ],
};
```

The canonical adapter is a server-side field `beforeValidate` hook. It passes `undefined` through for Payload required/default handling, returns normalized valid values, and converts Zod issues to Payload `ValidationError` entries with dot paths such as `gallery.0.alt`.

Consumer field hooks are cloned and preserved. Consumer `beforeValidate` hooks run before the package adapter. Native `validate` is not replaced or translated.

Keep all Payload and `@payloadcms/*` packages on the same exact version. Payload-generated types remain authoritative for persisted documents.
