---
title: Native Payload fields
description: Use the escape hatch without weakening canonical schema availability rules.
---

Use `field.native` for data-affecting Payload types not covered by a built-in factory.

```ts
import { field } from "@nexload-sdk/payload-schema";
import { z } from "zod";

const location = field.native({
  payload: { type: "point" },
  schema: z.tuple([z.number(), z.number()]),
});
```

Without `schema`, the field still compiles for Payload but is omitted from the schema context. A group or array containing it also becomes schema-unavailable; the picker reports the first blocking descendant path. Static defaults require a schema, while `dynamicDefaultValue` remains allowed.

Layout and UI fields such as rows, tabs, and collapsibles do not represent entity data and are rejected. Compose those directly in the Payload collection around `entity.payload.pick(...)`.

Native `validate` and hooks remain consumer-owned. The package only appends its canonical hook when a schema exists.
