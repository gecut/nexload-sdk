## Exported API Summary

Import the following from `@nexload-sdk/logger`. The testing helper has its own subpath.

| Export | Signature | Example and behavior |
|---|---|---|
| `logger` | `const logger: Logger` | `import { logger } from "@nexload-sdk/logger"`. The lazy proxy resolves the current configuration on each call. |
| Default export | `export default logger` | `import logger from "@nexload-sdk/logger"`. The default and named exports share the same proxy. |
| `getPayloadLoggerConfig` | `getPayloadLoggerConfig(): { options: pino.LoggerOptions; destination?: { write(line: string): void } }` | Node.js Payload configuration bridge. Call `configureLogger()` before `buildConfig()`; rebuild Payload configuration after forced reconfiguration. |
| `configureLogger` | `configureLogger(options: LoggerOptions): Logger` | `configureLogger({ service: "shop-api" })` configures the runtime. |
| `withLogContext` | `withLogContext<T>(bindings: LogBindings, fn: () => T): T` | `withLogContext({ requestId: "req-123" }, handleRequest)` runs the handler with request bindings where async context is supported. |
| `getLogContext` | `getLogContext(): LogBindings` | `const { requestId } = getLogContext()` reads the current bindings. |
| `TRACE_HEADER` | `const TRACE_HEADER: "x-trace-id"` | `response.headers.set(TRACE_HEADER, traceId)` sends the trace ID in the response. |
| `resolveTraceId` | `resolveTraceId(headers: Headers \| Record<string, string \| undefined>): string` | `resolveTraceId(request.headers)` reuses an incoming ID matching `/^[A-Za-z0-9-]{8,64}$/` or generates a UUID. |
| `traceHeaders` | `traceHeaders(): Record<string, string>` | `const outbound = new Headers(traceHeaders())` copies the active trace header. With no active trace ID it returns an empty record. |
| `DEFAULT_REDACT_PATHS` | `const DEFAULT_REDACT_PATHS: readonly string[]` | `const paths = [...DEFAULT_REDACT_PATHS, "customer.nationalCode"]` copies the defaults for inspection or reuse. |

```ts
interface Logger {
  trace(objOrMsg?: object | Error | string, msg?: string): void;
  debug(objOrMsg?: object | Error | string, msg?: string): void;
  info(objOrMsg?: object | Error | string, msg?: string): void;
  success(objOrMsg?: object | Error | string, msg?: string): void;
  warn(objOrMsg?: object | Error | string, msg?: string): void;
  error(objOrMsg?: object | Error | string, msg?: string): void;

```

`log.isLevelEnabled("debug")` checks whether debug events will be emitted. Levels map to `trace: 10`, `debug: 20`, `info: 30`, `success: 35`, `warn: 40`, `error: 50`, and `fatal: 60`.

```ts
interface LoggerOptions {
  service: string;
  level?: LogLevel;
  release?: string;
  instance?: string;
```

On Node, pretty output defaults to enabled outside production; `destination` takes precedence. Browser and Edge use pino browser output and ignore these server stream options. Server log records include `service`, `pid`, and ISO `time`, plus configured `release`, `instance`, and `environment` fields.

***

Root export conditions `browser`, `edge-light`, and `worker` select the browser bundle; `import` and `require` select Node bundles. The `./testing` subpath provides Node import and require bundles.

Default redaction covers the ten sensitive keys listed in the [guide](../guides/) at the top level and one level below, plus the explicit header and body paths. It does not recursively redact deeper keys. The censor defaults to `[REDACTED]`. Error serialization includes type, a 500-character message, a matching uppercase code, at most two nested causes, and a stack outside production.

# Production Guides & Recipes

Configure the logger per runtime and use request context, trace headers, redaction, and error serialization.

**Topic:** guides
**Package:** `@nexload-sdk/logger` v4.1.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/logger/guides/
## Configure Once per Runtime

Call `configureLogger` in the Node.js or Bun service entry point. Configure a browser bundle separately at its startup if it needs custom settings. The lazy logger uses environment fallbacks before configuration. `SERVICE_NAME` defaults to `unknown`, `RELEASE` supplies the release, and `LOG_LEVEL` defaults to `info` in production and `debug` elsewhere.

A second configuration call returns the existing logger and emits a warning with event `logger.reconfigure.ignored`. Use `force: true` when you intentionally need to replace it.

### Next.js Instrumentation

Configure the logger in `instrumentation.ts`. Each server runtime initializes its own logger when Next.js invokes `register`.

```ts
export async function register() {
  const { configureLogger } = await import("@nexload-sdk/logger");
  configureLogger({ service: "shop-web", release: process.env.RELEASE });
}
```

***

## Request Context and Trace Propagation

Resolve the trace ID at the request boundary and attach it to a request scope. Node's async context carries bindings through awaited calls. Nested scopes merge bindings, with inner values taking precedence.

```ts
import { logger, resolveTraceId, traceHeaders, withLogContext } from "@nexload-sdk/logger";

const log = logger.child({ module: "inventory" });

export async function GET(request: Request) {
  const requestId = crypto.randomUUID();
  const traceId = resolveTraceId(request.headers);

  return withLogContext({ requestId, traceId }, async () => {
    const startedAt = performance.now();
    const upstream = await fetch("https://inventory.example.com/availability", {
      headers: traceHeaders(),
    });
    log.info({
      event: "inventory.request.completed",
      status: upstream.status,
      durationMs: performance.now() - startedAt,
      outcome: upstream.ok ? "success" : "failure",
    }, "Inventory request completed");
    return upstream;
  });
}
```

### Edge and Browser

`withLogContext` calls the callback directly, and `getLogContext()` returns an empty object. Browser output uses pino browser records; server `pretty` and `destination` settings do not apply. Bind IDs with `logger.child({ requestId, traceId })` and forward the trace explicitly with `{ [TRACE_HEADER]: traceId }`.

## Redaction

```ts
import { configureLogger } from "@nexload-sdk/logger";

configureLogger({
  service: "shop-api",
  redact: { paths: ["customer.nationalCode"] },
});
```

### Path Coverage

The default censor is `[REDACTED]`. Default key patterns cover `password`, `token`, `secret`, `apiKey`, `authorization`, `cookie`, `otp`, `phone`, `mobile`, and `merchant` at the top level and one level below it. The defaults also cover `req.headers.authorization`, `req.headers.cookie`, `headers.authorization`, `headers.cookie`, `body`, and `req.body`.

Extra paths extend the defaults unless you set `replaceDefaults: true`. Deeper fields such as `user.profile.phone` require an explicit path. Keep log fields limited to IDs and safe metadata, and keep secrets out of message strings.

***

## Errors

Pass the error under `err`, or pass an `Error` as the first argument. Log it once at the boundary that handles it. Let errors propagate to that boundary when the caller handles them.

```ts
import { logger } from "@nexload-sdk/logger";

const log = logger.child({ module: "orders" });

export function orderFailure(err: unknown) {
  log.error({ err, event: "order.request.failed" }, "Order request failed");
  return new Response("Unable to process order", { status: 500 });
}
```

### Serialized Fields

The serializer includes the error type, up to 500 characters of its message, an optional code that matches `/^[A-Z][A-Z0-9_]{1,99}$/`, and up to two nested causes (three error records including the root). Non-Error values become a type and string message. Stack traces are included outside production.

***

## Testing

Use `createTestLogger` from `@nexload-sdk/logger/testing` to assert on emitted events. It captures parsed entries independently of the global configuration, so tests do not need to reset shared state.

```ts
import { createTestLogger } from "@nexload-sdk/logger/testing";

const { logger, entries, clear } = createTestLogger({ service: "test", level: "info" });

logger.success({ event: "order.lifecycle.placed", orderId: "123" }, "Order placed");

entries[0]?.event; // "order.lifecycle.placed"
clear();
```

Inject the test logger into the code under test instead of mocking the shared `logger`.

***

## Libraries

A library that logs imports the shared logger and never calls `configureLogger`. The host application owns configuration, so the library's module children follow it. Before the application configures the logger, calls use the environment fallbacks described above.

***

## Logging Architecture

Create one child per module. Log on request completion, outbound provider calls, job completion, and business state transitions. Aggregate loop results and log the summary once. Give each event a stable past-tense `domain.entity.action` name and a short message. Add `durationMs` and `outcome` to timed operations, and `attempt` to retry events.

Use `info` for lifecycle summaries, `success` for business milestones, `warn` for handled degradation, and `error` for unexpected failures. Reserve `fatal` for conditions that prevent the process from continuing. Use `debug` and `trace` for diagnostics. Skip logs for successful health checks.

See the [logger skill](https://github.com/gecut/nexload-sdk/tree/main/skills/logger) for boundary, field, and level rules.

***

## Troubleshooting & Migration from v4

### 1. Global Setup and Children's Bindings

Replace `NexloadLogger` and `createGlobalLogger` with startup configuration and the shared `logger` export. Pass an object to `child`, such as `logger.child({ module: "orders" })`.

### 2. Renderers and Level Filters

Replace custom renderer APIs with `pretty` or `destination`. Update structured-log queries and filters to use lowercase output labels; the Node pretty stream displays uppercase labels. Existing uppercase `LOG_LEVEL` values are accepted.

### 3. Tests and Error Fields

Replace `@nexload-sdk/logger/log-test` with `createTestLogger` from `@nexload-sdk/logger/testing`. Review redaction coverage and pass errors under `err` or as the first argument.

# Guides & Recipes

Persian and Iranian utilities.

**Topic:** guides
**Package:** `@nexload-sdk/persian` v0.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/persian/guides/
## Digits

```ts
import { parseNumber, formatNumber } from "@nexload-sdk/persian/digits";
const amount = parseNumber("۱۲٬۳۴۵"); // 12345
const display = formatNumber(amount); // Persian digits and grouping
```

`formatNumber` accepts finite numbers with absolute value below `1e21`; strings use `parseNumber`. Invalid input throws `RangeError`.

```ts
import { normalizePersianText, toSearchKey } from "@nexload-sdk/persian/text";

```

```ts
import { validateIranMobile, toE164Mobile } from "@nexload-sdk/persian/mobile";
const result = validateIranMobile("۰۹۱۲۳۴۵۶۷۸۹");
const international = toE164Mobile("۰۹۱۲۳۴۵۶۷۸۹"); // +989123456789
```

## Identity

```ts
import { validateNationalCode, normalizePostalCode } from "@nexload-sdk/persian/identity";
const nationalCode = validateNationalCode("۰۰۸۴۵۷۵۹۴۸");
const postalCode = normalizePostalCode("۱۲۳۴۵۶۷۸۹۰");
```

Legal IDs, postal codes and landlines also have `validate`, `normalize` and `isValid` functions.

## Bank

```ts
import { validateCardNumber, detectBankByCard, validateSheba } from "@nexload-sdk/persian/bank";
const card = validateCardNumber("۶۰۳۷۹۹۷۵۱۲۳۴۵۶۷۸");
const bank = detectBankByCard("۶۰۳۷۹۹۷۵۱۲۳۴۵۶۷۸");
const sheba = validateSheba("IR820540102680020817909002");
```

Card and Sheba validation checks format and checksum; Sheba check digits must be 02–98. Bank detection is researched, best-effort data from two independent source reviews (card BINs and Sheba codes); unknown or unresolved identifiers return `null`. Merged and dissolved banks keep their original id because legacy cards and Sheba numbers still exist; `getBank(id).mergedInto` names the successor (for example `ghavamin` → `sepah`, `ayandeh` → `melli`). Blu shares Saman BIN `621986` and is detected from digits 7–8 (`18`/`19`).

## Money

```ts
import { money, convertMoney, formatMoney, parseMoney } from "@nexload-sdk/persian/money";
const price = money(12500, "IRR");
const tomans = convertMoney(price, "IRT"); // 1250 IRT
const label = formatMoney(price, { displayUnit: "IRT" });
const parsed = parseMoney("۱۲٬۵۰۰", "IRR");
```

`formatMoney` returns `null` for an invalid amount or unit. Amounts are safe integers with explicit units: 10 IRR = 1 IRT. `parseMoney` rejects decimal text, including zero fractional digits, and unsafe integers. When `displayUnit` conversion is not divisible, `formatMoney` keeps the source unit unless rounding is given. `convertMoney` throws for invalid or non-divisible conversion without rounding.

## Date

```ts
import { parseJalaliDate, formatJalali, jalaliToGregorian } from "@nexload-sdk/persian/date";
const date = parseJalaliDate("۱۴۰۳/۰۱/۰۱");
const label = formatJalali(date, { format: "short", timeZone: "Asia/Tehran" });
const gregorian = jalaliToGregorian(1403, 1, 1);
```

Supported Jalali years are 1–3176. Outside that range, calendar conversion APIs throw `RangeError`; formatters and parsers return `null`. Date formatters and parsers return `null` for bad input or an invalid time zone. ISO date-only strings are wall midnight and offsetless ISO date-time strings are wall time in `options.timeZone`, defaulting to `Asia/Tehran`. Date-times accept `T` or a space and offsets `Z`, `±HH`, `±HHMM`, or `±HH:MM`. ISO fractional seconds accept 1–9 digits and truncate to milliseconds, with or without an offset. Parsing a Jalali date requires a four-digit year and defaults to noon in that zone. Formatting uses deterministic calendar conversion, not the `Intl` Persian calendar; timezone conversion needs `Intl` timezone data.

## Relative time

```ts
import { formatRelativeTime } from "@nexload-sdk/persian/relative";
const label = formatRelativeTime("2024-03-20T12:00:00+03:30", {
  now: "2024-03-20T13:00:00+03:30",
  timeZone: "Asia/Tehran",

```

Counts in relative labels are at least one; 45–59 seconds displays one minute.

## Zod

Install Zod `>=4.1.0 <5` separately for this optional `./zod` subpath.

```ts
import { iranMobileSchema, moneySchema } from "@nexload-sdk/persian/zod";
const mobile = iranMobileSchema({ format: "e164" }).safeParse("۰۹۱۲۳۴۵۶۷۸۹");
const price = moneySchema("IRT").safeParse(1250);
```

## Forms: normalize, store, display

```ts
import { validateIranMobile, formatIranMobile } from "@nexload-sdk/persian/mobile";
const input = "۰۹۱۲۳۴۵۶۷۸۹";
const result = validateIranMobile(input);
if (result.ok) {
  const canonicalForStorage = result.value; // store 09123456789
  const display = formatIranMobile(canonicalForStorage);
}
```

Validate and normalize at input, persist the canonical value, then format on output. On failure use the reason and message tables below.

## Canonical forms

| Value | Canonical form |
|---|---|
| Mobile | `09XXXXXXXXX` |
| E.164 mobile | `+989XXXXXXXXX` |
| National code | 10 ASCII digits |
| Postal code | 10 ASCII digits |
| Legal ID | 11 ASCII digits |
| Landline | 11 ASCII digits, `0[1-8]` followed by 9 digits |
| Card | 16 ASCII digits |
| Sheba | `IR` followed by 24 ASCII digits |

# persian — Optimization

Production choices for @nexload-sdk/persian.

**Topic:** optimization
**Package:** `@nexload-sdk/persian` v0.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/persian/optimization/
## Keep currency units explicit

Use integer amounts and specify IRR or IRT. `parseMoney` rejects decimal strings and unsafe integers.

## Check the calendar boundary

Supported Jalali years run from 1 to 3176. Conversion functions can throw a RangeError outside this range.

## Plan money conversion rounding

When a display-unit conversion is not divisible, `formatMoney` keeps the source unit unless a rounding mode is supplied. `convertMoney` throws without rounding.

## Provide timezone data

Timezone conversion in `./date` and `./relative` requires host `Intl` timezone data. The package supports Node.js, Bun, Edge, and browsers.

# persian — Playground

Try Persian prices, mobile numbers, national codes, cards, Sheba and Jalali dates.

**Topic:** playground
**Package:** `@nexload-sdk/persian` v0.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/persian/playground/
## Try it

Type a value in Persian, Arabic or Latin digits and pick a mode. Every result comes from `@nexload-sdk/persian` running in your browser.

## Modes

| Mode | Input | Functions used |
| --- | --- | --- |
| `IRR` / `IRT` | A whole number of rials | `parseMoney`, `formatMoney` from `@nexload-sdk/persian/money` |
| `mobile` | An Iranian mobile number in any common form | `validateIranMobile`, `toE164Mobile`, `formatIranMobile` from `@nexload-sdk/persian/mobile` |
| `national-code` | A 10-digit کد ملی | `validateNationalCode` from `@nexload-sdk/persian/identity` |
| `card` | A 16-digit bank card, separators allowed | `validateCardNumber`, `formatCardNumber`, `detectBankByCard` from `@nexload-sdk/persian/bank` |
| `sheba` | A Sheba (IBAN) starting with `IR` | `validateSheba`, `formatSheba`, `detectBankBySheba` from `@nexload-sdk/persian/bank` |
| `jalali` | An ISO date-time with an offset | `formatJalali` from `@nexload-sdk/persian/date`, time zone `Asia/Tehran` |

## Read the result

* Fractional prices are invalid. When a rial amount cannot convert exactly to tomans, the formatter keeps rials: `12501` in `IRT` shows `۱۲٬۵۰۱ ریال`.
* Invalid identifiers show the SDK's reason code, for example `invalid_checksum`. Use the same codes in your own error messages.
* Try `۰۹۱۲۳۴۵۶۷۸۹` in `mobile`, `۰۰۸۴۵۷۵۹۴۸` in `national-code` and `IR820540102680020817909002` in `sheba`.
