# healthcheck-bun — Optimization

**Topic:** optimization
**Package:** `@nexload-sdk/healthcheck-bun` v3.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/healthcheck/bun/optimization/
## Interpret missing memory limits

The Bun adapter reads process memory when available and returns null for container limits. The memory check reports degraded with this adapter.

## Restrict diagnostic routes

Protect endpoints that expose Bun runtime and server metrics.

## Keep runtime metrics in diagnostics

`bunRuntimeInfoCheck` and `bunServerMetricsCheck` default to diagnostics and are noncritical.

This adapter is designed for Bun. It does not read Linux cgroups, so missing memory limits are not container limits.

# healthcheck — Optimization

Production choices for @nexload-sdk/healthcheck.

**Topic:** optimization
**Package:** `@nexload-sdk/healthcheck` v5.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/healthcheck/core/optimization/
## Reserve liveness for the process

Keep database, cache and remote HTTP checks in readiness when dependency outages should stop traffic without restarting the process.

## Protect diagnostics

Expose a minimal public probe. Restrict detailed reports and metrics to authorized callers.

## Bound probe execution

The manager defaults to a 1,000 ms timeout per check and eight concurrent checks. Tune these limits for the dependencies being probed.

## Profiles do not filter output

Profiles are hints for checks and collectors, not report filters. Use `toHealthJson()` or `stringifyHealthJson()` to control response details.

**Canonical page:** https://gecut.github.io/nexload-sdk/packages/healthcheck/next/optimization/

IP and CIDR filtering support IPv4 and require trustProxy. Enable it only when the reverse proxy strips and sets the configured header.

The route adapter supports Next.js Node.js and Edge runtimes. Use `runtime = "nodejs"` when the manager uses the Node adapter.

# healthcheck-payload — Optimization

Production choices for @nexload-sdk/healthcheck-payload.

**Topic:** optimization
**Package:** `@nexload-sdk/healthcheck-payload` v3.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/healthcheck/payload/optimization/
## Bound readiness query cost

Choose a small collection, use depth zero and supply a narrow where clause for frequent polls.

## Interpret probe failures

The Payload query check is critical for readiness and noncritical for diagnostics. A failed query reports PAYLOAD\_QUERY\_FAILED.

## Keep the default query small

The check defaults to `limit: 1`, `depth: 0`, and readiness. Frequent heavy queries can overload the database.

## Decide whether an empty collection is unhealthy

Set `expectedMinDocuments` only when an empty collection represents an operational failure, such as missing required seed configuration.

# logger — Optimization

Production choices for @nexload-sdk/logger.

**Topic:** optimization
**Package:** `@nexload-sdk/logger` v5.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/logger/optimization/
## Extend redaction for deeper objects

Default redaction covers keys at the top level and one level below it. Add explicit paths for sensitive fields deeper in the object.

## Configure once

Call `configureLogger()` at startup. A subsequent call without `force: true` keeps the existing configuration.

## Respect browser and Edge behavior

Browser and Edge builds use Pino browser output. `withLogContext` is pass-through, and `pretty` and `destination` do not configure a server stream.

## Rebuild Payload configuration after replacement

A forced logger reconfiguration requires rebuilding Payload configuration created with `getPayloadLoggerConfig()` to pick up the change.

# payload-fields — Optimization

Production choices for @nexload-sdk/payload-fields.

**Topic:** optimization
**Package:** `@nexload-sdk/payload-fields` v4.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/payload-fields/optimization/
## Normalize strings before field hooks

Install payloadFieldsPlugin() when REST or Local API callers send money values as strings. It normalizes Persian digits and separators before Payload parses number fields.

## Send integers from numeric clients

Pass minor-unit integers when the client already owns numeric conversion.

## Handle nested slug uniqueness

Automatic collision suffixes apply only to top-level slugs. For slugs inside arrays, groups, or named tabs, use `unique: false` to avoid relying on suffixing.

## Order field plugins deliberately

The plugin sees collections and globals present when it runs. Place plugins adding money fields before it, respecting its order of 900.

# payload-hooks — Optimization

Production choices for @nexload-sdk/payload-hooks.

**Topic:** optimization
**Package:** `@nexload-sdk/payload-hooks` v3.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/payload-hooks/optimization/
## Declare the auth collection

Declare an auth collection in the config to include it in auditing. Payload creates its implicit users collection after plugins run.

## Interpret write events in context

Write events from afterChange and afterDelete run before the database transaction commits.

## Avoid read auditing by default

Read auditing is off by default. When enabled, `find` logs once per request with a count, while `findByID` logs the document ID.

## Treat audit output as logs

The plugin does not persist database audit records. Authentication auditing covers successful logins and password resets, not failed logins.

# payload-operations — Optimization

Production choices for @nexload-sdk/payload-operations.

**Topic:** optimization
**Package:** `@nexload-sdk/payload-operations` v2.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/payload-operations/optimization/
## Keep outputs encodable

Use a codec or overwrite for output and declared error data that need conversion. A one-way transform cannot be encoded by the server.

## Preserve access control

Pass overrideAccess: false and req when a handler calls a Payload Local API on behalf of the caller.

## Bound request bodies

Requests over 1 MiB return `413 PAYLOAD_TOO_LARGE` by default. Set `maxBodyBytes` when the operation needs a larger body.

## Separate server and universal imports

The `./server` subpath requires Node.js 20.9 or newer. The root, contract, errors, client, CMS, and timeout plugin subpaths are universal.

# payload-schema — Optimization

Production choices for @nexload-sdk/payload-schema.

**Topic:** optimization
**Package:** `@nexload-sdk/payload-schema` v3.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/payload-schema/optimization/
## Choose optionality for projections

A plain pick(keys) makes all picked keys required. Set the optional option when the projection should respect optional fields.

## Preserve block metadata

Reserve id, blockName and blockType in block definitions. Reusing those names throws INVALID\_FIELD\_CONFIGURATION.

## Keep server code out of client bundles

Use the universal root entry for shared schemas. Import the `./payload` compiler only in Node.js Payload configuration.

## Choose codec-safe transformations

Custom schema transforms are not codec-safe for `z.encode`. Use `.refine()` or `.overwrite()` when schemas serve as operation outputs.

# persian — Optimization

Production choices for @nexload-sdk/persian.

**Topic:** optimization
**Package:** `@nexload-sdk/persian` v1.0.0
**Canonical page:** https://gecut.github.io/nexload-sdk/packages/persian/optimization/
## Keep currency units explicit

Use integer amounts and specify IRR or IRT. `parseMoney` rejects decimal strings and unsafe integers.

## Check the calendar boundary

Supported Jalali years run from 1 to 3176. Conversion functions can throw a RangeError outside this range.

## Plan money conversion rounding

When a display-unit conversion is not divisible, `formatMoney` keeps the source unit unless a rounding mode is supplied. `convertMoney` throws without rounding.

## Provide timezone data

Timezone conversion in `./date` and `./relative` requires host `Intl` timezone data. The package supports Node.js, Bun, Edge, and browsers.

Extend node.json for a backend package, react.json for a React library or next.json for a Next.js app.
