# Logger v5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `packages/refactoring/logger` (v4.1.0, custom renderers) with `packages/logger` v5: a thin layer over pino, configured once per runtime, safe by default, with full docs, a docs-site section and an enforcing agent skill.

**Architecture:** pino is the engine (Node build) and `pino/browser` the Edge/browser engine; our code is only the once-config, a lazy proxy `logger`, defaults (levels, redaction, error serializer, base fields), AsyncLocalStorage context, trace helpers, a dev pretty stream and a test logger.

**Tech Stack:** TypeScript 5.9.3, pino ^10.4.0, `@nexload-sdk/bundler` (esbuild), `node --test` `.mjs` tests against `dist/`, Astro Starlight (`apps/docs`), Changesets, pnpm workspaces.

**Spec:** `docs/superpowers/specs/2026-11-23-logger-v5-design.md` (read it first; this plan restates every value it pins).

## Global Constraints
- Package path `packages/logger`, name `@nexload-sdk/logger`, version bump **major** → `5.0.0` via changeset.
- `pino` `^10.4.0` is the only new runtime dependency. No `pino-pretty`, no worker-thread transports.
- Must **not** depend on `@nexload-sdk/env` (env depends on logger).
- Env fallbacks only: `SERVICE_NAME` (default `"unknown"`), `LOG_LEVEL`, `RELEASE`.
- Levels: `trace 10, debug 20, info 30, success 35, warn 40, error 50, fatal 60`; output label lowercase. Default level: `LOG_LEVEL` else `info` when `NODE_ENV === "production"`, else `debug`.
- Redaction censor `"[REDACTED]"`. `DEFAULT_REDACT_PATHS` = for each of `password, token, secret, apiKey, authorization, cookie, otp, phone, mobile, merchant`: both `key` and `*.key`; plus `req.headers.authorization, req.headers.cookie, headers.authorization, headers.cookie, body, req.body`.
- Error serializer on key `err`: `{ type, message (sliced to 500), code (only if /^[A-Z][A-Z0-9_]{1,99}$/), stack (only when NODE_ENV !== "production"), cause (recursive, depth ≤ 3) }`.
- `TRACE_HEADER = "x-trace-id"`; valid incoming id `/^[A-Za-z0-9-]{8,64}$/`, else `crypto.randomUUID()`.
- Second `configureLogger` without `force` → returns existing logger, emits one `warn` with `event: "logger.reconfigure.ignored"`.
- Base fields: `service`, optional `release`, `instance`, `environment`, plus pino `pid`, ISO `time` (`pino.stdTimeFunctions.isoTime`).
- Public exports exactly as in the spec's "Public API" block. Removed: `NexloadLogger`, renderer types, `./log-test` subpath, `createGlobalLogger`.
- Default export stays the `logger` proxy (keeps `import logger from "@nexload-sdk/logger"` working).
- Docs rule (AGENTS.md): never document behavior not in `src/`; update README + `docs/packages/` in the same change.
- Never commit `.enola/`. Never edit `dist/` by hand.

## Review Focus
1. A library module does `const log = logger.child({ module: "x" })` at import time, before `configureLogger` → later calls must use the configured service/level/redaction. (Task 1)
2. `logger.error(new Error("boom"))` (Error as first arg, no object) → serialized under `err`, not `{}`. (Task 2)
3. Circular object passed as bindings → no throw, line still written. (Task 2)
4. `{ user: { profile: { phone } } }` (2 levels deep) → NOT redacted by defaults; behavior is documented, not silently assumed. (Task 2 test pins it; Task 6 documents it)
5. `withLogContext` across `await` boundaries and in two concurrent requests → each line carries its own `requestId`. (Task 3)

**SKILL.md content (frontmatter + sections, follow `skills/healthcheck/core/SKILL.md` shape):**
- `name: logger`
- `description:` "MUST be loaded before writing, changing or reviewing ANY log call, console.* call, catch block, error handling, job/worker, outbound HTTP/provider call, route handler or observability code in a project that uses @nexload-sdk/logger. Decides whether a log is needed, its level, event name and fields, and what must never be logged. Do not use for metrics/health endpoints (use healthcheck skills)."
- Sections: Purpose; Trigger boundary; Source of truth (`packages/logger/src`); Required inspection (README, `src/index.ts`); **Decision flow (conditional)** as a numbered gate the agent walks for every candidate log:
  1. Is this code a boundary (inbound request, outbound call, job run, domain state transition, process lifecycle)? If no → do not log (pure functions, loops, getters). In a loop → aggregate and log once after.
  2. Is it a caught error? If you rethrow or return it upward → do not log. If you handle it here (fallback, retry, swallow, respond) → log once here with `{ err }`.
  3. Choose level from the table in `references/level-and-event-rules.md`.
  4. Name `event` as `domain.entity.action` past tense (`order.payment.verified`, `sms.delivery.failed`), plus short `msg`.
  5. Fields: ids only (`orderId`, `userId`, `provider`), `durationMs` + `outcome` (`success|failure|retry`) for timed ops, `attempt` for retries. Never secrets, OTP, phone, full bodies, provider payloads, tokens.
  6. Use `logger.child({ module })` once per module; never `console.*`; never create pino directly.
  7. Request scope: wrap handlers with `withLogContext({ requestId, traceId })`; forward `traceHeaders()` on outbound calls.
- **Required log points table** (conditional "if X then write Y"): app start (`info`, `app.lifecycle.started`, release), app shutdown/fatal (`fatal`), request summary (`info` one per request: method, route, status, durationMs), outbound provider call (`info` on success with durationMs; `warn` on retry; `error` when final failure), job run (`info` summary: scanned/sent/failed counts), domain milestone (`success`: `payment.attempt.verified`, `order.lifecycle.placed`), validation failure from user input (`debug`, not error), auth failure (`warn`, no credentials), config fallback used (`warn`), health check pass (nothing).
- Anti-patterns with before/after examples: double logging, logging in loops, `console.log`, logging request body, string-concatenated messages with data instead of fields.
- Verification checklist the agent must run before finishing: `rg "console\.(log|info|warn|error)" src` → none in app code; every `catch` either rethrows without logging or logs once with `{ err }`; every new `event` follows the naming rule.
